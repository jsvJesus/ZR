# Road Segments

Цель: автоматически показывать дороги Arizona, Aspen и California и редактировать
узлы, ширину и материал отдельных сегментов в Level editor.

Ограничения: не создавать/запускать тесты, приложения и сборки. Проверка чтением
исходников, разбором исходных данных и поиском ссылок. Оригинальные файлы не менять.

- [x] World/Roads: читать v4 DAT (контрольные точки, 36-байтовые вершины,
  индексы), выбирать дороги по LevelData.xml, материалы по room.mat.
- [x] Сохранять исходную запечённую геометрию; сегмент — интервал между двумя
  узлами, 50 поперечных шагов. Изменения узлов деформируют исходную поверхность
  и соседние сегменты; UV и исходные высоты сохраняются без изменений узлов.
- [x] Автозагрузка в LevelWorkspace для существующих уровней. Отдельный
  road-segments.json с правками, версией и проверкой соответствия источнику.
- [x] DX11: текстуры, нормали, прозрачность, приоритет, подсветка сегмента,
  ограничение дальности, освобождение ресурсов при смене уровня.
- [x] Level editor / Road Segments: список дорог и сегментов, переход камерой,
  редактирование узлов/касательных/ширины, выбор материала и DDS, сохранение.
- [x] Статически проверить пути, форматы, загрузку/смену уровня, обработчики XAML,
  совместимость C# и изменения через git diff --check.

Наблюдения: все найденные DAT имеют версию 4 и 50 шагов на интервал. Вершины
уже имеют координаты мира. XML содержит устаревшие позиции и повторные ссылки
California: они не являются основанием автоматически переносить запечённый меш.
Одна DAT-дорога загружается один раз. Диагностика показывает повторы и расхождения.
Некоторые исходные дороги Aspen лежат вне карты и имеют Y=0; не исправлять их
эвристическим масштабированием. Для ручного исправления предусмотреть узлы и
явную установку высот узлов по Terrain.
Текстуры из ObjectsDepot пока отсутствуют; использовать цвет из room.mat,
показывать отсутствие DDS и позволять выбрать локальный DDS.

Статическая проверка: все 380 DAT согласованы с 50 шагами на сегмент и
18 индексами на полосу между соседними рядами; ручки имеют семантику Bézier
(производная 3 * ручка). Исправлены общие позиции/нормали границ.
Сохранение вызывается также общей командой File и перед закрытием; ожидается
уже начатая запись. API сверены с локальными Avalonia/SharpDX XML.
Сборки, тесты и приложения не запускались. Визуальная проверка не выполнялась.

Исправление по скриншоту пересечения Terrain/дорог:
- Чтение данных показало, что 21%/20%/33% выбранных точек DAT Arizona/Aspen/California
  ниже подробного Terrain более чем на 2 см, хотя DAT совпадает с исходным шагом 1.
- Привязка к точным треугольникам текущего resident/overview с сохранением UV,
  исходного превышения и ручных правок высоты; кэш по неизменяемым сеткам тайлов.
- Согласование граничных высот подробной и обзорной сеток, обновление GPU/CPU
  сетки при изменении соседства и перенос skirts вниз от общей границы.
- Непрозрачный depth prepass и цвет по draw_priority; полупрозрачные края
  не отсекают нижнюю дорогу. Picking выбирает верхнюю совпадающую поверхность.
- FollowTerrain по умолчанию true, совместимость старых правок и режим исходной
  высоты DAT доступны. Проверка только чтением исходников/исходных данных.
